# slip-finder

Поиск **кода авторизации** и **номера чека** по логам банковского модуля ARCUS 2, когда слипы терминала не печатаются.

Для возврата по карте касса спрашивает код авторизации и номер чека исходной оплаты. Если слип не распечатан, эти данные остаются только в логах ARCUS, и кассиру их не найти. slip-finder читает эти логи, складывает операции в свою базу и показывает на кассовом ПК страницу быстрого поиска по сумме, времени и последним цифрам карты.

- Работает локально на кассовом ПК, страница доступна только с него (`127.0.0.1`). Данные никуда не отправляются.
- Хранит операции дольше, чем сам ARCUS: тот удаляет логи через `NDAYS` дней (параметр в `cashreg.ini`).
- Один exe без установки Python, иконка в трее.

## Установка

1. Скачайте `slip-finder-<версия>-win64.zip` со страницы [Releases](../../releases) и распакуйте.
2. Запустите `install.bat` двойным кликом, **без** «Запуск от имени администратора».
   - Программа ставится в `%LOCALAPPDATA%\Programs\slip-finder`, права администратора не нужны.
   - Если логи ARCUS лежат не в `C:\Arcus2\logs`, установщик спросит путь.
   - Появятся ярлык **«Найти чек»** на рабочем столе и запись в автозагрузке.
3. Программа запустится сама: иконка чека у часов и страница поиска в браузере. Первый разбор логов может занять до минуты.

Для обновления запустите `install.bat` из новой версии: он закроет старую и заменит её.

Windows может предупредить о неизвестном издателе, потому что exe не подписан. Нажмите «Подробнее» → «Выполнить в любом случае» или соберите exe сами (см. «Разработка»).

## Как искать

| Что ввести | Что найдётся |
|---|---|
| `258`, `258,50`, `2.00` | операции на эту сумму |
| `14:30` | операции в 14:15–14:45 |
| `1234` | карта с последними цифрами 1234 (или сумма 1234 ₽) |
| `visa`, `mir`, `a1b2c3` | тип карты, код авторизации |
| `258 14:30` | условия можно сочетать |

Период (Сегодня / Вчера / … / Всё) выбирается кнопками. Новые оплаты появляются в течение 15–30 секунд, а кнопка **«⟳ Сканировать сейчас»** проверяет логи немедленно.

На карточке операции крупно показаны **код авторизации** и **номер чека**, у каждого своя кнопка «Копировать». Для возврата берите данные с карточки **«Оплата»**: у самого возврата свой номер чека. Серые карточки — неоплаченные попытки (отказ банка, карта не считана), их код для возврата не подходит.

## Трей и настройки

- Клик по иконке в трее открывает поиск. В меню: «Сканировать логи сейчас» и «Выход».
- Внизу страницы есть ссылка **«Настройки»** с папкой логов ARCUS. Настройки хранятся в `%LOCALAPPDATA%\slip-finder\settings.json`.
- База операций: `%LOCALAPPDATA%\slip-finder\slips.db`, журнал программы: `%LOCALAPPDATA%\slip-finder\slip-finder.log`.

Операции попадают в базу, только пока программа запущена, поэтому она стоит в автозагрузке.

## Как это работает

Разбирается формат логов ARCUS 2 (проверено на версии 2.0.0.48 с пин-падом NewWay):

- Один файл на операцию, имя `YYMMDDhhmmss.log`, кодировка cp1251, у строк префикс `<unix-время> - `.
- Строка после `External Command`: поля через ESC, `класс␛id␛валюта␛сумма`. Класс 1: id 1 = оплата, 11 = возврат, 5/9 = отмена (см. `ops.ini`). Классы 2/3/9 (сверка, TMS, пинг) пропускаются.
- Блок `Starting output to [chek.out]` … `Output to file finished`: код ответа, маска карты, TID, код авторизации, платёжная система, статус, сумма в копейках, RRN. **Пустые поля ARCUS не пишет**, поэтому поля опознаются по виду: 12 цифр = RRN, 8 цифр = TID, маска со `*`, 6 букв/цифр (регистр любой) = код.
- Номер чека есть только в hex-дампе ответа пин-пада после `RecvOWTags`: тег `5F22`, 2 байта little-endian.
- Одобрено только при коде ответа `000`: у отказа `116` (недостаточно средств) код авторизации тоже бывает. Тексты отказов берутся из `rc_res.ini` ARCUS.
- Возврат выводит RRN и код **исходной** оплаты, поэтому запись операции идентифицируется по имени файла, а не по RRN.

## Разработка

```
py -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt pytest
.venv\Scripts\python -m pytest
.venv\Scripts\python -m slip_finder --logs tests\fixtures --db %TEMP%\t.db
build.bat   # → dist\slip-finder.exe + dist\install.bat
```

Логи в `tests/fixtures` **синтетические**: их генерирует `tools/make_fixtures.py`, формат как у ARCUS, данные выдуманные. Не кладите в репозиторий настоящие логи: в них данные покупателей и магазина (маски карт, сроки действия в EMV-дампах, суммы, RRN, коды). Если для отладки нужен реальный лог, сначала пропустите его через `tools/sanitize_log.py`, а публиковать его всё равно не стоит.
